Two credential families, split by transport, not by convenience.

## Per-repo read-only Ed25519 deploy keys — all git-protocol work

Carry [tier-1 polling](../architecture/polling.md) and the [synth job's](../architecture/synth-job.md)
clone. **User jobs never clone and have no deploy-key access** — they consume `source.tar.gz` from
S3. Generated by `millwright repo add`, stored in SSM under the CMK, installed via the App's
Administration permission (or printed for manual add).

Deploy keys are used **always**, including when everything is healthy: *the everyday path is the
outage path*. The App token never touches tier 1.

Why SSM and not Secrets Manager: an Ed25519 private key is ~400 B and SSM's standard tier is free.
Secrets Manager would roughly 10× the polling stack's cost at 50 repos.

## Per-deployment GitHub App — REST-only work

Check runs and tier-2 PR polling. Created by `millwright setup` via the manifest flow.

**Permissions**: Contents: read, Checks: write, Commit statuses: write, **Pull requests: read**
(required by the tier-2 `pulls` endpoint), Administration: write (deploy-key install).

Rate limit ≥5,000 req/hr per installation, cap 12,500.

**Installation tokens are minted on demand and cached in memory only, per consumer Lambda** — never
in DynamoDB, never as rotated secrets. If a durable cache is ever demonstrated necessary, the
pre-approved shape is a CMK-encrypted blob in the *polling* table with item TTL = token expiry.
Not v1.

## Administration: write — blast radius, documented

App permissions are per-App, not per-call, so reducing this after onboarding would need a second
App — not v1 complexity. **A stolen App PEM permits installing an attacker deploy key on every
watched repo**, i.e. persistent private-code read. That is why the PEM sits behind the two-gate
SSM+CMK posture (`ssm:GetParameter*` **and** `kms:Decrypt`).

PAT mode is the tighter-scoping alternative.

## Fine-grained PAT fallback

`millwright setup --pat` uses **commit statuses instead of check runs**, with **identical context
names**, so branch protection works the same either way.
